# Spec: CLI, Claude Director Loop & Claude Code Skill

**Change:** 007-cli-claude-skill
**Created:** 2026-09-07
**Status:** 🟡 Draft

## Overview

Two new packages — `@claudevid/cli` (`packages/cli`, bin `claudevid`) and `@claudevid/claude`
(`packages/claude`, the Anthropic-facing generation library) — plus `.claude/skills/video-generator/`,
wire the six shipped packages (001–006, 008) into something a human or Claude Code can actually
run end to end: `init → generate → validate → render`.

This increment does **not** touch `packages/core`, `packages/motion`, `packages/renderer-canvas`,
`packages/encoder-ffmpeg`, `packages/audio`, `packages/layer-code`, or `packages/layer-captions` —
every dependency listed below is an existing, shipped export (verified on disk; see Dependencies).

**Decisions carried from proposal.md's Open Questions** (stated here per Rule 1 — think before
coding, don't leave these for the build loop to guess):

- **Credentials:** `ANTHROPIC_API_KEY` environment variable only. No Claude-Code-session reuse in
  v1 — that couples the CLI to a host environment for a marginal convenience gain.
- **Default model:** a single named constant (`DEFAULT_MODEL_ID`), overridable via
  `claudevid.config.json`'s `model` field or `--model`. Tests assert the override path works, not
  the literal id (it will need bumping as models change; that's a config edit, not a code change).
- **Repair attempt budget:** default 3, configurable (`--repair-attempts` / config
  `repairAttempts`). On exhaustion: throw with **only the last attempt's diagnostics** (not the
  full history) — matches proposal.md's "fail loudly with the last diagnostics printed".
- **Committed vs. generated schema:** `packages/claude/schemas/video-spec.schema.json` and
  `packages/claude/prompts/video-director.md` are both committed and both generated by one script
  (`packages/claude/scripts/generate-assets.ts`). A vitest test regenerates both in-memory and
  diffs against the committed files — drift fails `pnpm -r run test`, no separate CI workflow
  needed (none exists in this repo yet).
- **Brand kit format:** JSON (`claudevid.config.json`), validated by a Zod schema in
  `packages/claude/src/config-schema.ts` with an inferred TS type — same schema-is-the-type
  pattern as `packages/core/src/schema.ts`. Trivially readable by the model and by the skill's
  scripts, no build step required to read it.
- **Does `generate` render by default?** No. `generate` writes and validates a spec, then stops.
  `--render` opts in to running the full render pipeline afterward.
- **Batch failure policy:** skip-and-record. One job's failure is written to the batch's manifest
  with a `failed` status and does not stop the remaining queue; `claudevid batch` exits 1 only if
  the queue itself could not run (e.g. an unreadable job directory), not because some jobs failed
  (that's a normal, expected outcome for an overnight batch — the manifest is the source of truth).
- **Captions layer assembly (new, forced by an existing constraint):** `packages/layer-captions`'s
  `captionsLayerSchema` requires a non-empty `words: WordTiming[]` array
  (`packages/layer-captions/src/schema.ts:61`) — no Claude director can emit frame-accurate word
  timings at generation time. So a `captions` layer is never something `generate` produces
  directly; it is inserted by the render pipeline (FR9) as an explicit `--captions` opt-in, after
  narration synthesis and forced alignment have produced real `WordTiming[]` data. This is exactly
  the assembly step `captionsLayerSchema`'s own header comment anticipates ("assembled by whoever
  assembles the VideoSpec from 006's scene-window data").

## Requirements

### Functional Requirements

- **FR1 — `claudevid init`** (`packages/cli/src/commands/init.ts`). Scaffolds, in the current
  directory: `claudevid.config.json` (brand kit + defaults, FR7), `.claudevid/` with a
  `.gitignore` containing `*` (cache dir per `@claudevid/audio`'s `resolveCacheRoot`, never
  committed), and `specs/example.json` (one worked example copied from
  `packages/claude/examples/simple-title.json`). Refuses to overwrite an existing
  `claudevid.config.json` unless `--force` (mirrors `tools/motion-preview`'s no-clobber pattern).

- **FR2 — `claudevid validate <spec>`** (`packages/cli/src/commands/validate.ts`). Reads the file,
  `JSON.parse`s it, runs `@claudevid/core`'s `parseSpec`. On success: prints scene count and total
  duration, exit 0. On failure: prints every `Diagnostic` (`path`, `message`, `suggestion?`) one
  per line, exit 1. Never throws a raw `ZodError` or parse exception past this command's own
  error boundary — a malformed-JSON file is reported as one diagnostic at pointer `/`, not a stack
  trace.

- **FR3 — `claudevid preview <spec>`** (`packages/cli/src/commands/preview.ts`). Runs the shared
  render pipeline (FR9) at a fixed 1280×720 working resolution — scaled via `createRenderer(1280,
  720)` and `renderFrame`'s `opts.scale` (per `renderer-canvas`'s own doc comment: construct a
  smaller renderer and pass the ratio, never resample after the fact) — encoded with
  `resolveProfile("preview", ...)`. `--watch` re-runs the pipeline on file change (`fs.watch`, no
  new dependency, debounced 250ms). `--sheet <path>` instead renders N evenly-spaced frames
  (default 6, reusing the frame-count/validation shape of `tools/motion-preview`'s `parseArgs`,
  but implemented independently in `packages/cli` — `tools/motion-preview` stays a standalone dev
  tool per its own package, not a CLI dependency) into one contact-sheet PNG via
  `@napi-rs/canvas`.

- **FR4 — `claudevid render <spec>`** (`packages/cli/src/commands/render.ts`). Runs the shared
  render pipeline (FR9) at the spec's native resolution, `resolveProfile("final", ...)`, and
  writes the muxed output to `--out` (required, never derived from the spec — same rule
  `tools/motion-preview` already enforces for its own `--out`).

- **FR5 — `claudevid generate "<prompt>"`** (`packages/cli/src/commands/generate.ts`,
  `packages/claude/src/generate.ts`). Calls the Anthropic Messages API with
  `packages/core`'s `generateJsonSchema()` output as a tool/structured-output schema (FR10) and the
  assembled director prompt (FR11) as the system prompt. Runs `parseSpec` on the model's JSON
  output; on failure, feeds the returned diagnostics back to the model for up to
  `repairAttempts` total attempts (including the first); on final failure, throws with the last
  attempt's diagnostics. On success, writes the spec to `--out` (default `specs/<slug>.json`) and
  runs `claudevid validate` on it once more as a final integrity check. Does not render
  (`--render` opts in, then runs FR4's pipeline against the freshly-written spec).

- **FR6 — `claudevid batch <dir>`** (`packages/cli/src/commands/batch.ts`). Reads every `*.json`
  (prompt-list entries `{ "prompt": string, "out"?: string }`) or `*.spec.json` (pre-built specs)
  file in `<dir>`, runs each through generate-then-optionally-render (mirrors FR5/FR4, one job per
  file) sequentially (bounded by `--concurrency`, default 1), and writes
  `<dir>/batch-manifest.json` — one entry per job: `{ file, status: "ok" | "failed", error?,
  outputPath? }`. A failed job is recorded and skipped (see Decisions above); the manifest is
  written incrementally (after each job) so a killed batch still leaves a usable partial manifest.

- **FR7 — `claudevid.config.json` / brand kit** (`packages/claude/src/config-schema.ts`,
  `packages/cli/src/config.ts`). Zod schema: `{ model?: string, repairAttempts?: number,
  brand?: { palette?: string[], fontFamily?: string, logoPath?: string }, voice?: string }`. All
  fields optional with documented defaults — an empty `{}` is a valid config. Loaded once per CLI
  invocation from `./claudevid.config.json` (cwd), merged under explicit `--flag` overrides
  (flags win).

- **FR8 — director prompt assembly** (`packages/claude/src/prompts/build-director-prompt.ts`,
  `packages/claude/scripts/generate-assets.ts`). Assembles `prompts/video-director.md` from:
  `@claudevid/motion`'s `exportCatalogue()` (preset names + channels), `@claudevid/layer-code`'s
  `BUNDLED_LANGS`/`BUNDLED_THEMES`, and the loaded brand kit (FR7) — never hand-edited, generated
  and committed (Decisions above). A scene requesting a `captions` layer type in `generate`'s
  output is never valid — the prompt explicitly instructs the model not to emit `type:
  "captions"` layers (FR9 supplies them at render time instead).

- **FR9 — shared render pipeline** (`packages/cli/src/render-pipeline.ts`, used by FR3/FR4/FR5's
  `--render`/FR6). One function, `runRenderPipeline(spec, opts): Promise<void>`: (1) for scenes
  with `duration: "auto"`, `computeAudioDurations` then `compileTimeline(spec, {audioDurations})`,
  else `compileTimeline(spec, {})`; (2) if `opts.captions` is set, for each scene with narration,
  synthesize each block (`getOrSynthesize`), run `align()` against the synthesized audio and the
  block's reference text, convert block-relative `WordTiming[]` to timeline-absolute seconds
  (block offset + the scene's `SceneWindow.startFrame / spec.fps`), and insert a `type:
  "captions"` layer with the resulting `words` into a working (in-memory only) copy of the spec
  scene, before step (1)'s `compileTimeline` call; (3) `probe()` capabilities, `createRenderer`,
  `createTempRun`, `createEncodePipe` (profile per caller), render every frame via
  `renderer.renderFrame`, `pipe.write`/`pipe.finish()`; (4) if any scene has narration,
  `buildAudioGraphArgv` + `muxOutput` the synthesized tracks against the silent video into
  `opts.outputPath`; if no narration anywhere in the spec, the silent video *is* the output
  (renamed/moved to `opts.outputPath`, no mux step). Always disposes the renderer and cleans up
  the temp run, including on error (`try/finally`, per `tools/bench`'s existing precedent).

- **FR10 — `packages/claude/schemas/video-spec.schema.json`**: committed output of
  `generateJsonSchema()` (`@claudevid/core`), regenerated by `generate-assets.ts`, drift-checked
  by a test (Decisions above).

- **FR11 — `.claude/skills/video-generator/`**: `SKILL.md` (usage, the two scripts below, points
  at the committed schema/examples), `schemas/video-spec.schema.json` and `examples/*.json`
  (byte-identical copies of `packages/claude`'s, synced by the same `generate-assets.ts` and
  drift-checked the same way), `scripts/validate.ts` and `scripts/render.ts` — thin wrappers that
  `execFileSync` the already-built `packages/cli/dist/cli.js` with the script's own argv forwarded
  verbatim (no duplicated logic; `SKILL.md` states the one-time `pnpm build` prerequisite).

- **FR12 — chapter-based generation** (`packages/claude/src/chapters.ts`). `outline(prompt,
  opts): Promise<ChapterOutline[]>` (one Anthropic call, no structured-output schema needed — a
  plain `{ title: string, summary: string }[]`), then one `generateSpec` call per chapter (FR5's
  repair loop, reused) carrying a `StyleContract` (brand kit + preset catalogue + a running array
  of prior chapters' `{ title, summary }`, not their full scene JSON — keeps later-chapter prompts
  small). `mergeChapters(specs): VideoSpec` concatenates each chapter's `scenes` in order and
  throws `SceneIdCollisionError` (naming every colliding id) if any scene id repeats across
  chapters — no automatic renaming/prefixing (repairing a collision silently would invalidate any
  cross-chapter reference the model itself wrote).

- **FR13 — `claudevid models install`** (`packages/cli/src/commands/models.ts`). Thin wrapper
  around `@claudevid/audio`'s `installModels`, printing progress and exit code (this is the CLI
  surface AC10 of change 006's spec explicitly deferred to this change).

- **FR14 — `claudevid bench`** (`packages/cli/src/commands/bench.ts`). Thin wrapper invoking
  `tools/bench`'s existing `runBench(argv)` — no logic duplicated, `packages/cli` takes a
  workspace dependency on `@claudevid/bench`.

### Non-Functional Requirements

- **NFR1** — `packages/cli` and `packages/claude` follow every existing package's structure:
  `src/`, `test/`, `tsup.config.ts`, `vitest.config.ts`, `tsconfig.json` extending
  `tsconfig.base.json`.
- **NFR2** — No new CLI-argument-parsing dependency (no `commander`/`yargs`) — manual `argv`
  parsing per `tools/motion-preview/src/args.ts`'s precedent: pure `parseArgs(argv)` functions,
  `ArgError` for user-facing failures, injectable `fs`/`process` seams for testability.
- **NFR3** — Every command's core logic is testable without a real Anthropic API call, a real
  FFmpeg binary, or a real ONNX model — `generate.ts`'s Anthropic client, `render-pipeline.ts`'s
  `probe`/`synthesize`/`align`, and `models.ts`'s `installModels` are all called through their
  existing injectable seams (`@claudevid/audio` and `@claudevid/encoder-ffmpeg` already provide
  these; `packages/claude`'s Anthropic client wrapper adds one for itself).
- **NFR4** — `packages/cli` depends only on workspace packages (`@claudevid/core`,
  `@claudevid/motion`, `@claudevid/renderer-canvas`, `@claudevid/encoder-ffmpeg`,
  `@claudevid/audio`, `@claudevid/layer-code`, `@claudevid/layer-captions`, `@claudevid/claude`,
  `@claudevid/bench`) plus `@napi-rs/canvas` (already a dependency elsewhere) and the Anthropic SDK
  (new, confined to `packages/claude`).
- **NFR5** — `packages/cli`'s `cli.ts` imports `@claudevid/layer-code` and
  `@claudevid/layer-captions` unconditionally (for their `registerLayer`/`registerPainter` side
  effects) before dispatching any command — otherwise `code`/`captions` layers would
  schema-validate but silently fail to render (the exact footgun both packages' own `index.ts`
  header comments warn about).

## Acceptance Criteria

- **AC1** — `claudevid init` in an empty directory creates `claudevid.config.json`,
  `.claudevid/.gitignore`, and `specs/example.json`; running it again without `--force` exits 1 and
  changes nothing; with `--force` it overwrites.
- **AC2** — `claudevid validate` against each of `packages/claude/examples/*.json` exits 0; against
  a deliberately invalid fixture (missing required field) exits 1 and prints a diagnostic
  including that field's JSON pointer.
- **AC3** — `runRenderPipeline` against a spec with two "auto"-duration narrated scenes and no
  captions produces a muxed output file whose probed duration matches the sum of measured
  narration durations within `mux.ts`'s existing tolerance (reusing 006/008's own duration-match
  test fixture pattern — this AC does not re-derive that tolerance, it reuses it).
- **AC4** — `runRenderPipeline` with `opts.captions: true` against a narrated scene produces a
  compiled `Timeline` containing exactly one `captions` layer for that scene, whose `words[0].start`
  equals that scene's `SceneWindow.startFrame / fps` plus the narration's own leading silence (i.e.
  timeline-absolute, not block-relative) — verified via the injected `synthesize`/`align` fixtures
  (NFR3), no real model.
- **AC5** — `generate`'s repair loop: a fixture Anthropic client that returns an invalid spec on
  attempt 1 and a valid one on attempt 2 succeeds and reports 2 attempts; one that never returns a
  valid spec within `repairAttempts` throws, and the thrown error's diagnostics equal exactly the
  last attempt's (not attempt 1's).
- **AC6** — `mergeChapters` on two chapters with disjoint scene ids concatenates cleanly, in
  chapter order; on two chapters sharing one scene id, throws `SceneIdCollisionError` naming that
  id, and does not partially merge.
- **AC7** — `packages/claude`'s committed `schemas/video-spec.schema.json` and
  `prompts/video-director.md`, and `.claude/skills/video-generator/schemas/video-spec.schema.json`
  and `/examples/*.json`, are byte-identical to what `generate-assets.ts` produces right now — the
  drift test fails the moment any of `@claudevid/core`'s schema, `@claudevid/motion`'s catalogue,
  or `@claudevid/layer-code`'s bundled langs/themes changes without a regeneration.
- **AC8** — `claudevid batch` over a 3-job directory where job 2's file is deliberately malformed
  JSON: jobs 1 and 3 succeed, job 2 is recorded `failed` in `batch-manifest.json` with a
  diagnostic-shaped error, process exit code is 0.
- **AC9** — `claudevid models install` (CLI surface only; the underlying primitive is
  covered by change 006's own AC10) exits 0 and prints a success line when the injected
  `installModels` fixture resolves, exits 1 and prints the thrown error's message when it rejects.
- **AC10** — `pnpm -r run build`, `pnpm -r run test`, `pnpm -r run lint` all pass from a clean
  checkout, and every existing package's suite (001–006, 008) is unaffected.

## Edge Cases

- `claudevid render --out` pointing at an existing file: refuses unless `--force` (same no-clobber
  rule as `tools/motion-preview`, applied consistently here).
- A spec with zero narrated scenes and `--captions` set: no captions layers are inserted anywhere
  (nothing to align against) — not an error, a no-op for that flag.
- `generate`'s prompt asks for more scenes than fit one Claude response (the doc's own stated
  failure mode): out of scope for a single `generateSpec` call — that is exactly what FR12's
  chapter path exists for; `generate` (no `--chapters`) is documented as short-form only.
- `ANTHROPIC_API_KEY` unset: `generate`/`batch` fail fast with a clear message before making any
  network call, not a raw 401 from the SDK.
- `batch` job file is neither valid prompt-list JSON nor a valid spec: recorded as `failed` with a
  message naming which shape check it failed, same as any other job failure (FR6).
- Two chapters' style contracts disagree because the brand kit changed mid-run (config edited
  between chapter calls): out of scope — the brand kit is read once per `generate` invocation
  (FR7), not re-read per chapter.

## Notes

- `tools/motion-preview`'s contact-sheet renderer is a standalone dev tool
  (`private: true`, no `bin` beyond its own) and is deliberately **not** made a dependency of
  `packages/cli` — FR3's `--sheet` reimplements the same small grid-of-frames idea independently,
  consistent with `tools/bench`'s own header comment that its harness is invoked directly, "never
  through a `claudevid` CLI subcommand."
- Real Anthropic API calls, real FFmpeg, and real ONNX inference are exercised only in gated
  integration tests, following 005/006/008's existing precedent — this spec does not add a new
  tier, it reuses it.
- Cloud TTS providers, a hosted MCP server, Remotion export, and multi-model directors remain out
  of scope (unchanged from proposal.md).
